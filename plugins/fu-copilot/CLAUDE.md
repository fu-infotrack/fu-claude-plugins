## Design

- **Delegating to an external agent CLI** (`fu-copilot`): same split as `fu-review-prs` — the steps that must not be guessed at are plain bash in the caller (`dispatch.sh`, `verify.sh`), the long run goes to a sub-agent whose context never returns. The container choice is **not** about reliability (a self-report is unreliable wherever it sits) but about context: runs are 10–113 min and the four sub-agents with recorded usage burned 60k–125k tokens each. Four constraints, all measured in session `773e2fc4` (2026-08-27, 20 dispatches over `InfoTrackCredit`), none guessed: (1) **Copilot cannot read under `~/.claude`** — `Permission denied and could not request permission from user`, and it fails *silently*: one run could not read its brief, inferred there was nothing to do, and did a **no-op force-push** while reporting success. `dispatch.sh` refuses such a brief path rather than staging a copy; logs there are fine, the shell writes those. (2) **The brief must be prompt text, not a path** — inlined into `-p`, then *confirmed* by grepping the launched process's `/proc/<pid>/cmdline` for its first 32 chars. Copilot is exec'd directly, no launcher script, so the PID is Copilot's own. **Both sides of that comparison must be normalised the same way** (fixed v0.3.0, reported by a peer session with a repro): the marker was newline-stripped while `tr '\0' ' '` leaves real newlines in the cmdline, so any brief whose first 32 chars crossed a line break reported `BRIEF_REACHED_PROCESS: no` with the full text sitting in argv — a 10-char `/implement` first line did it, and it cost a killed run that had already done real work. The staged copy also **announces its own absolute path** in an appended footer, since the caller cannot name a mktemp path it never chose: measured as a two-run A/B, a brief saying only "a copy is staged" sent Copilot to a repo-scoped `glob **/*brief*` that found nothing, while one naming the path had it read the file as its second action (n=1 each way — directional). Keep the "outside the repo, a repo-scoped glob will not find it" clause: it is part of the measured stimulus. The brief deliberately does **not** move into the target worktree — an untracked `tmp/` would fail `WORKTREE_CLEAN`, and the ignore rule that fixes it (`tmp/.gitignore` containing exactly `*`; a `!.gitignore` negation breaks it) is per-machine state no plugin can guarantee in every target repo. Note also that a background job's harness instruction to use `$CLAUDE_JOB_DIR/tmp` points straight at the refused `~/.claude` path — documented in SKILL.md, since the refusal is correct and the collision is the surprise. (3) **Never foreground** — the Bash tool caps `timeout` at 600000 ms; `setsid` + `kill -0 <pid>` polling, never `pgrep -f 'copilot -p'` (parallel runs across worktrees match each other's patterns). (4) **A self-report is not a completion signal** — seen three times in one session, so every check reads git or the log. `LOSSLESS` deliberately reports when it is **vacuous** because HEAD never moved, and a check with no input prints `SKIP`, never `PASS` (asserted by a test). Flags: `--allow-all-tools` always (else it prompts and **hangs**), **`--excluded-tools task` always** (v0.5.0) — Copilot's own sub-agent tool is off, because a dispatch is already one scoped brief and fan-out is expensive where this plugin cannot see it: measured 2026-09-09 from a real run's usage JSON, `agentMetrics.main` was 2908309000 nanoAiu against 375050720000 for the single `general-purpose` sub-agent it spawned — **129x the parent**, drawn on the same session cap, and indistinguishable in the cumulative totals so `USAGE_RUN:` cannot attribute it. `--excluded-tools` not `--deny-tool`: the former removes the tool from the model's list (verified live — Copilot prints `Disabled tools: task` and `functions.task` vanishes from what it enumerates), the latter leaves it offered and burns a turn on a refused call. Tool name confirmed by asking a live `copilot -p` to list its registered tools; `read_agent`/`list_agents`/`write_agent` only read and write agent definitions and are left alone. No opt-out flag, deliberately. `--no-color` always — though **not sufficient**: measured 2026-09-01, the stats footer still emits raw ANSI escapes, so any grep over the log must tolerate them (a test pins the resume-handle extraction against an escape-wrapped line). `-s/--silent` **never** — it hides the `copilot --resume=<uuid>` handle. `--session-id` is a passthrough and **measured working** (2026-09-01): a caller-generated UUID becomes the session's own id and a second dispatch recalls the first turn, so a follow-up costs a short prompt instead of a re-sent ~5 KB brief -- the largest easy saving available, given that session used it in **0 of 24** invocations. Generate ids with `cat /proc/sys/kernel/random/uuid`; **`uuidgen` is absent on this host**, and an explicitly-passed empty flag value is now rejected rather than ignored (found when `--session-id "$SID"` with `SID` unset silently started a fresh session). The `~/.claude` read denial was re-confirmed live the same day, so it is current behaviour rather than history. **A 100 AI-credit session cap is passed by default** (v0.2.0) — `--max-ai-credits <n|off>`, minimum 30 per `copilot help limits`, rejected below that in `dispatch.sh` so it does not surface as a run that died instantly for no stated reason. This is the plugin's **first constraint taken from documentation rather than a measured run** (CLI 1.0.82; no run has been observed hitting the ceiling). The cap is documented as *soft* — usage is known only after a response returns — which introduces the very failure shape this plugin exists to catch: **a capped-out run stops between model calls with its work half-done and every git check still passing**. No git read can distinguish that from success, so it is **not graded**: `dispatch.sh` always passes `--usage-output-file` (beside the log) and `verify.sh check --usage` prints it as a `USAGE:` line, with `CREDITS:` on the agent receipt. Deliberately **not** done — grepping the log for an exhaustion string: the documented `Session limits: N/M AI credits used.` line appears on *healthy* runs at 50/75/90%, so the obvious `session limit` pattern would FAIL passing runs, and the reached-limit wording has never been seen. A guessed pattern is a check that lies, which is worse than a number the caller reads. The self-driving review loop is deliberately out of v1 — its safety rests on these gates, and the gates are the testable part. See `plugins/fu-copilot/docs/DESIGN.md`.
